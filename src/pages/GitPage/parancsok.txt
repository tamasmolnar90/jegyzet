A git push origin main helyett érdemes a git push -u origin main parancsot használni az első feltöltésnél.
A -u (vagy --set-upstream) kapcsoló megjegyzi, hogy a helyi main ág a távoli origin/main-hez tartozik,
így a jövőben elég lesz csak annyit beírnod, hogy git push vagy git pull.

create … (új file)
add … (új funkció)
remove … (törlés)
update … (módosítás)
fix bug in … (hiba javítás)
refactor … (kód javítás funkció változtatás nélkül)
rename … (átnevezés)

Prefix: feat
Jelentés: Új funkció (feature)
Példa: feat: add search bar

Prefix: fix
Jelentés: Hibajavítás
Példa: fix: correct search result count

Prefix: refactor
Jelentés: Refaktorálás, átszervezés funkcióváltozás nélkül
Példa: refactor: simplify header logic

Prefix: style
Jelentés: Kódstílus, formázás, white space, pontosvessző
Példa: style: fix indentation in Search component

Prefix: docs
Jelentés: Dokumentációval kapcsolatos változás
Példa: docs: update README with usage instructions

Prefix: test
Jelentés: Tesztek hozzáadása vagy módosítása
Példa: test: add unit test for Search

Prefix: chore
Jelentés: Apró háttérmunkák (pl. build script frissítés)
Példa: chore: update dependencies

Prefix: perf
Jelentés: Teljesítményoptimalizálás
Példa: perf: improve rendering performance of Search component

Prefix: build
Jelentés: Build rendszer vagy függőségek változása
Példa: build: add webpack config for production

Prefix: ci
Jelentés: ci (Continuous Integration) beállítások
Példa: ci: add GitHub Actions workflow

Prefix: revert
Jelentés: Egy korábbi commit visszavonása
Példa: revert: feat: add search component

### HASZNOS TUDNIVALÓK ###
##########################

A git három területtel dolgozik: 
– Working Directory: ahol szerkeszted a fájlokat 
– Staging Area (index): ide kerül, amit commitolni fogsz 
– Repository: ide kerülnek a commitok

- A commit üzenetek legyenek rövidek és érthetőek, projekttől függ a nyelvezetük, de legyen egységes.
- A git pull két műveletből áll: fetch + merge.
- A git push csak a commitolt változtatásokat tölti fel.
- Ágkezelés a gyakorlatban: - main/main mindig stabil - development ág ahol egyesítjük a változtatásokat - fejlesztés külön feature brancheken.
- A .gitignore fájlban lehet megadni, hogy mi NE kerüljön a repo-ba.
- Ha valamit véletlenül törölsz, a git log és git checkout segítségével visszaállítható.
- Merge konfliktus esetén a fájlban jelzések jelennek meg (<<<<<< HEAD stb.), ezeket kézzel kell javítani, gui rendszeren ajánlott.
